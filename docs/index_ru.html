Обзор

Abloom — это комплексная боевая модификация, которая вводит систему элементального резонанса с 14 уникальными элементами. Каждый элемент имеет свою механику накопления, специальные статусные эффекты и стратегическое применение.

Ключевые особенности:

  • 14 типов элементов: FIRE, PHYSICAL, WIND, WATER, EARTH, ICE, ELECTRIC, ENERGY, NATURAL, QUANTUM, ETHER, LIGHT, SHADOW, PRISMATIC
  • Система резонанса: Накапливайте элементальные очки через атаки, чтобы вызвать мощные взрывы резонанса при 100 очках
  • 18 статусных эффектов: Burn, Wetness, Stun, Freeze, Shock, Break, Rupture, Bloom, Overload, Windswept, Corruption, Taunt, Dispersion, Eclipse, Critical Gain, Prism, Fluorescence, Suppression
  • Многоступенчатое оружие: Оружие может иметь до 4 стадий атаки с разными элементами и множителями накопления
  • Система критических ударов: Пользовательские атрибуты CRIT_CHANCE и CRIT_DMG с бонусами от оружия
  • Сопротивления брони: Части брони могут обеспечивать сопротивление или слабость к определённым элементам (-0.99 до 0.99)
  • Элементальные снаряды: Стрелы и снаряды могут наследовать элемент от оружия стрелка или быть принудительно изменены на конкретный элемент
  • Система приоритетов урона: Разрешение конфликтов с другими модами через приоритетную модификацию урона (HIGHEST=300, HIGH=200, NORMAL=0, LOW=-100, LOWEST=-300)
  • Отображение чисел урона: Визуальная обратная связь с настраиваемыми числами урона и статусными текстами
  • Поддержка датапаков: Настройка оружия, брони и свойств мобов без написания кода
  • Developer API: Комплексный Java API для интеграции с модами
Совет: Порог резонанса по умолчанию составляет 100 очков. Базовое накопление — 1 очко за удар, модифицируется множителями оружия и статусными эффектами, такими как Wetness (+50% за уровень).

LIGHT Взрыв светового резонанса, применяет эффект Dispersion, который увеличивает получаемый урон в зависимости от типа входящего урона: Physical +15%, Fire +15%, Wind +30%, Water +30%, Earth +15%, Ice +15%, Electric +30%, Energy +15%, Natural +15%, Quantum +15%, Ether +15%, Light +30%, Shadow +20%, Prismatic +30% 14 секунд (280 тиков)
SHADOW Взрыв теневого резонанса, применяет эффект Eclipse (защита цели снижена на 10% + 10% за каждый дополнительный негативный эффект, макс. 50%) 14 секунд (280 тиков)
PRISMATIC Призматический урон НЕ накапливает очки резонанса. Когда на цели есть эффект Prism, призматический урон конвертируется в сохранённый тип элементального урона. Если эффект Prism не активен, попадание по цели с любым эффектом резонанса применяет эффект Prism на 40 секунд и конвертирует последующий призматический урон в этот тип элементального урона. 40 секунд (800 тиков)
Примечание: Поскольку призматический урон не накапливает очки резонанса, поле accumulation_multiplier не будет на него влиять.

Система приоритетов урона

Система приоритетов урона разрешает конфликты, когда несколько модов одновременно изменяют урон. Модификаторы сортируются по приоритету (от высшего к низшему) и вызываются в порядке регистрации (FIFO) для равных приоритетов.

Приоритет Значение Описание Когда использовать
HIGHEST 300 Высший приоритет Для критически важных модификаций
HIGH 200 Высокий приоритет Когда нужно обработать ДО Abloom
NORMAL 0 Приоритет по умолчанию Для простых модификаторов
LOW -100 Низкий приоритет (использует Abloom) Когда нужно обработать ПОСЛЕ большинства модов
LOWEST -300 Очень низкий приоритет Когда нужно обработать последним
Примечание: Abloom API использует приоритет LOW (-100) для обработки урона. Моды с приоритетом > 0 вызываются ДО Abloom, а моды с приоритетом <= 0 вызываются ПОСЛЕ Abloom.

Система оружия

Регистрация оружия

Оружие может быть зарегистрировано с элементальными свойствами. Многоступенчатое оружие может иметь до 4 стадий атаки, каждая со своим типом элемента и множителем накопления. Стадии сбрасываются после перезарядки на основе скорости атаки.

Пример многоступенчатой регистрации:

// Регистрация оружия с 2 стадиями
ResourceLocation swordId = ResourceLocation.fromNamespaceAndPath("mymod", "dragon_sword");

// Стадия 1: Огненный элемент с множителем накопления 2x
ElementalWeaponRegistry.registerBuiltinWeaponWithStage(
    swordId,
    1,                              // номер стадии (1-4)
    ElementType.FIRE,
    2.0f,                           // множитель накопления
    0.15f,                          // шанс крита (общий)
    0.5f                            // урон крита (общий)
);

// Стадия 2: Физический элемент с множителем накопления 3x
ElementalWeaponRegistry.registerBuiltinWeaponWithStage(
    swordId,
    2,
    ElementType.PHYSICAL,
    3.0f,
    0.15f,
    0.5f
);

Пример одноступенчатой регистрации:

Для оружия, которое не требует нескольких стадий, используйте упрощённый метод регистрации:

// Регистрация простого огненного посоха с одноступенчатым поведением
ResourceLocation staffId = ResourceLocation.fromNamespaceAndPath("mymod", "fire_staff");

ElementalWeaponRegistry.registerBuiltinWeapon(
    staffId,                        // ID оружия
    ElementType.FIRE,               // тип элемента
    1.5f,                           // множитель накопления
    0.2f,                           // шанс крита
    0.75f                           // урон крита
);

Система критических ударов

Abloom добавляет два пользовательских атрибута для критических ударов:

  • CRIT_CHANCE (abloom:crit_chance): -2 до 2 (-200% до 200%). Максимум ограничен 2.0 (200%) для включения мульти-крита.
  • CRIT_DMG (abloom:crit_dmg): -10 до 10 (-1000% до 1000%). Применяется аддитивно от атрибутов сущности и значений оружия.

Система мульти-крита

Abloom поддерживает мульти-критические удары, которые наносят двойной критический урон. Общий шанс крита (атрибуты сущности + значения оружия, суммируются аддитивно) ограничен максимумом 2.0 (200%). Когда общий шанс крита превышает 100% (1.0), любое значение выше 1.0 даёт шанс сработать мульти-криту, который умножает результирующий критический урон на 2x.

Как это работает: Если у вас 150% шанс крита (1.5), вы гарантированно получаете как минимум один крит. Оставшиеся 0.5 (50%) дают вам 50% шанс сработать мульти-криту, нанося двойной критический урон. Мульти-криты отображаются с !!! в числах урона, а обычные криты показывают !!.

Значения крита оружия: 
// Получить шанс крита из стака оружия
float critChance = ElementalWeaponUtils.getCritChance(stack);

// Получить урон крита из стака оружия
float critDamage = ElementalWeaponUtils.getCritDamage(stack);

// Зарегистрировать оружие со значениями крита
ElementalWeaponRegistry.registerWeapon(
    myItem,
    ElementType.FIRE,
    2.0f,       // накопление
    0.25f,      // 25% шанс крита
    0.75f       // 75% урон крита
);

Combat API

Нанесение элементального урона

// Нанести элементальный урон
ElementDamageHandler.dealElementDamage(target, ElementType.FIRE, 10.0f);

// Нанести с пользовательским множителем накопления
ElementDamageHandler.dealElementDamage(target, ElementType.FIRE, 10.0f, 2.0f, attacker);

// Нанести с конкретными очками накопления
ElementDamageHandler.dealElementDamage(target, ElementType.FIRE, 10.0f, 50);

// Мгновенный урон (обходит некоторые модификаторы)
ElementDamageHandler.applyElementalDamageInstant(target, source, ElementType.FIRE, 10.0f, 1.0f);

Управление очками накопления

// Добавить очки накопления
ElementDamageHandler.addElementPoints(entity, ElementType.FIRE, 25);

// Получить текущие очки
int points = ElementDamageHandler.getElementPoints(entity, ElementType.FIRE);

// Сбросить конкретный элемент
ElementDamageHandler.resetElementPoints(entity, ElementType.FIRE);

// Сбросить все элементы
ElementDamageHandler.resetAllElementPoints(entity);

// Получить прогресс (0-100%)
int progress = ElementDamageHandler.getAccumulationProgress(entity, ElementType.FIRE);

Элементальные снаряды

// Зарегистрировать снаряд по типу сущности

// Принудительно установить конкретный элемент (переопределяет оружие стрелка)

ElementalProjectileRegistry.setInheritElementFromShooter(true);

Интеграция с модами

Система модификации урона

Зарегистрируйте модификаторы урона с приоритетами для интеграции с конвейером урона Abloom:

// Зарегистрировать модификатор с явным приоритетом
DamageModificationManager.registerModifier(myModifier, 200);  // HIGH - перед Abloom
DamageModificationManager.registerModifier(myModifier, -100); // LOW - после Abloom

// Зарегистрировать с приоритетом по умолчанию (0 = NORMAL)
DamageModificationManager.registerModifier(myModifier);

// Обработать урон вручную
float highPriorityDamage = DamageModificationManager.processHighPriorityDamage(
    target,
    source,
    baseDamage
);

float lowPriorityDamage = DamageModificationManager.processLowPriorityDamage(
    target,
    source,
    currentDamage
);

// Отладка: получить количество зарегистрированных модификаторов
int count = DamageModificationManager.getRegisteredModifierCount();

Полный пример интеграции

package com.example.mymod;

import com.auranite.abloom.*;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.Rarity;

public class MyModElements {

    public static final Item DRAGON_SWORD = new Item(new Item.Properties().rarity(Rarity.RARE));
    public static final Item ICE_BOW = new Item(new Item.Properties().rarity(Rarity.RARE));
    public static final Item IRON_CHESTPLATE = new Item(new Item.Properties().rarity(Rarity.COMMON));

    public static void init() {
        // Зарегистрировать элементальное оружие
        registerElementalWeapons();

        // Зарегистрировать сопротивления брони
        registerArmorResistances();

        // Зарегистрировать снаряды
        registerProjectiles();
    }

    private static void registerElementalWeapons() {
        // Меч дракона: огненный урон с множителем накопления 3x, 20% шанс крита, 60% урон крита
        ElementalWeaponRegistry.registerBuiltinWeapon(
            DRAGON_SWORD,
            ElementType.FIRE,
            3.0f,
            0.2f,
            0.6f
        );

        // Ледяной лук: ледяной урон с множителем накопления 2x
        ElementalWeaponRegistry.registerBuiltinWeapon(
            ICE_BOW,
            ElementType.ICE,
            2.0f,
            0.05f,
            0.5f
        );
    }

    private static void registerArmorResistances() {
        // Железный нагрудник: 30% сопротивления огню
        ArmorResistanceRegistry.registerArmor(
            IRON_CHESTPLATE,
            ElementType.FIRE,
            0.3f
        );
    }

    private static void registerProjectiles() {
        // Снаряды огненного шара: огненные
        ElementalProjectileRegistry.registerProjectile(
            EntityType.FIREBALL,
            ElementType.FIRE,
            1.5f
        );

        // Стрелы наследуют элемент от оружия стрелка
        ElementalProjectileRegistry.setInheritElementFromShooter(true);
    }
}
Рекомендации:
  1. Всегда проверяйте null при получении элементов из предметов
  2. Используйте значения конфигурации вместо жёсткого кодирования настроек отображения
  3. Регистрируйте в common setup (не только client или server)
  4. Тестируйте с /reload при использовании датапаков во время разработки
  5. Ограничивайте значения сопротивления между -0.99 и 0.99

Конфигурация элементального оружия

Оружие может быть настроено с атаками стадий или без них. Многоступенчатое оружие наносит разные типы элементов и значения накопления за удар, в то время как оружие с одним элементом поддерживает постоянное поведение.

Пример многоступенчатого оружия

Оружие может иметь несколько стадий атаки с разными элементами и множителями накопления:

{
  "item": "abloom:fire_stick",
  "stages": {
    "1": {
      "element": "PHYSICAL",
      "accumulation_multiplier": 10.0
    },
    "2": {
      "element": "PHYSICAL",
      "accumulation_multiplier": 10.0
    },
    "3": {
      "element": "FIRE",
      "accumulation_multiplier": 15.0
    },
    "4": {
      "element": "FIRE",
      "accumulation_multiplier": 35.0
    }
  },
  "base_element": "FIRE",
  "crit_chance": 0.5,
  "crit_damage": 1.0
}

Поля:

  • item: ID предмета (namespace:item_id)
  • stages: Стадии атаки с типом элемента и множителем накопления
    • Номера стадий должны быть последовательными (1, 2, 3, 4...)
    • element: Тип элемента для этой стадии (FIRE, WATER, ICE, и т.д.)
    • accumulation_multiplier: Сколько очков резонанса добавляет эта стадия
  • base_element: Тип элемента по умолчанию для оружия
  • crit_chance: Шанс критического удара (0.0 до 1.0)
  • crit_damage: Множитель урона критического удара (1.0 = 100% дополнительного урона)

Разбор примера: Пример fire_stick показывает оружие с 4 стадиями:

  • Стадии 1-2: Урон PHYSICAL с низким накоплением (10.0 каждая)
  • Стадия 3: Урон FIRE со средним накоплением (15.0)
  • Стадия 4: Урон FIRE с высоким накоплением (35.0)
  • 50% шанс крита с 100% дополнительным уроном крита
  • Базовый элемент — FIRE для расчётов сопротивления

Пример оружия с одним элементом (без стадий)

Для более простого оружия, которое всегда наносит один и тот же тип элемента без прогрессии стадий:

{
  "item": "abloom:water_blade",
  "basic_element": "WATER",
  "accumulation_multiplier": 12.0,
  "crit_chance": 0.3,
  "crit_damage": 0.8
}

Поля для оружия с одним элементом:

  • item: ID предмета (namespace:item_id)
  • element: Тип элемента для всех атак (обязательно)
  • accumulation_multiplier: Очки резонанса, добавляемые за удар (обязательно, если нет стадий)
  • crit_chance: Шанс критического удара (опционально, по умолчанию 0.0)
  • crit_damage: Множитель урона критического удара (опционально, по умолчанию 0.0)
Примечание: Если присутствует stages, поле accumulation_multiplier на корневом уровне игнорируется. Используйте стадии для сложного оружия с развивающимися паттернами урона или опустите стадии для постоянного оружия с одним элементом.

Конфигурация сопротивлений брони

Загрузка датапаков

  1. Поместите ваш датапак в .minecraft/saves/[worldname]/datapacks/
  2. Перезагрузите командой /reload
  3. Проверьте логи на сообщения подтверждения:
    • Loaded X elemental weapon configurations from datapacks
    • Loaded X armor resistance configurations from datapacks
Распространённые проблемы:
  • Проверьте правильность имён реестра предметов (используйте F3+H для расширенных подсказок)
  • Убедитесь, что значения элементов точно совпадают (FIRE, а не fire)
  • Проверьте, что значения сопротивления находятся в диапазоне от -0.99 до 0.99
  • ID типов сущностей должны быть действительными (например, minecraft:zombie)
