# Custom Elemental Damage Types via Datapack — Plan

## Goal
Prepare `ElementType.java` to support dynamically registered custom element types that can be loaded from datapacks, while preserving all 14 built-in enum values.

## Approach
- Keep `ElementType` as an enum with the existing 14 built-in values
- Add a static `ConcurrentHashMap` registry for custom `ElementType` instances
- Provide a public `registerCustomElementType(String name, String damageTypeId)` method
- Update lookup methods (`fromDamageTypeId`, `safeValueOf`) to also check the custom registry
- Add utility methods for introspection (`getAllElementTypes()`, `isCustomType()`, `getBuiltInTypes()`)

## Key Design Decisions
1. **Thread safety**: Use `ConcurrentHashMap` since registry may be populated during datapack loading on dedicated server thread
2. **Immutable custom types**: Once registered, custom `ElementType` instances are effectively immutable
3. **Validation**: Prevent duplicate names/damage type IDs, null values, empty strings
4. **Backward compatibility**: All existing code continues to work unchanged — `values()`, `valueOf()`, switch statements remain the same

## Files Modified
- `src/main/java/com/auranite/abloom/util/ElementType.java` — add registry and registration methods

## Files NOT Modified (out of scope)
- `ElementalWeaponData.java` — will be updated in a separate step to parse custom element types from JSON
- `ElementDamageHandler.java` — no changes needed (uses ElementType generically)
- `ElementalWeaponComponent.java` — uses `ElementType.name()` which works for custom types too
- `ElementalResistanceComponent.java` — iterates `ElementType.values()` which only returns built-in types; will need separate update
